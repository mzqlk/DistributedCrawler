## 管理会话执行规则

1. **开始前**：
   - 运行 `dotnet --list-sdks` 确认有 10.x，缺失时按 CLAUDE.md 的方法装到临时目录。
   - 运行 `git pull`，确认工作区干净。
2. **选任务**：取第一个“待开始”且依赖都“已完成”的任务，在本文件里把它改为“进行中”。
3. **派子代理**：
   - 从最新的 master 建分支 `task/Tn`。
   - 派一个子代理，直接在主工作区的这个分支上工作，不使用 worktree。
   - 交给它的内容：该任务的提示词原文，加上下文的“子代理通用要求”。
   - 等它结束后才能进行下一步。
4. **验收**：
   - 用 `git diff master...task/Tn` 审看改动，确认没有超出任务范围；按 CLAUDE.md 检查有没有个人信息。
   - 编译，跑全量测试（包括集成测试；DataAnalysis 有 pytest 时一并运行）。
   - 不通过时，把失败信息交回该子代理或另派一个修复。**同一任务两轮修复后仍失败，就停下来汇报。**
5. **收尾**：
   - 在总览表里把任务改为“已完成”，填上提交号。
   - 把子代理报告中的决定追加到“决策记录”，把界面复测步骤追加到“待用户复测”，然后提交这些文档改动。
   - 快进合并到 master（不能快进时先 rebase），推送，删除任务分支。
   - **本路线图授权：验收通过的任务可以直接推送到 master。**
6. **继续**：直接开始下一个任务，不需要等用户确认。
7. **结束**：全部完成或停下时，给用户一份简短汇报，包括：完成的任务和提交号、测试结果、决策记录摘要、待复测清单、遗留问题。

## 决策规则

**直接决定，然后记录理由**：
- 实现方案与库的选型；
- 默认参数；
- P2 及以下的问题修不修；
- 协议的向后兼容扩展（例如在枚举或消息末尾追加，同时更新 `ProtoContractTests`）；
- 新增状态值；
- 测试策略；
- 文档如何组织；
- 任务提示词里给了“默认”的事项。

**必须停下来问用户**：
1. 可能把个人信息、凭据，或来源不明的第三方代码推到公开仓库。
2. 不可逆或破坏性的操作：改写已推送的历史、强制推送、删除 `D:\毕设相关` 或用户本地 `crawler.db` 里的真实数据。
3. 需要付费、注册账号或申请 API 密钥。
4. 合规风险：违反目标网站的条款或限速要求，或者需要绕过反爬与验证码（项目边界明确不做反爬破解）。
5. 推翻已有技术选型或改变项目方向，例如替换 WPF 或数据库、删除已有功能。
6. 同一任务两轮修复后验证仍失败。

### T1 端到端集成测试

```text
为 Master–Worker 搭建可以自动运行的端到端集成测试，不启动 WPF 界面。
做法：
- 在测试中启动 Master 的 gRPC、调度、故障恢复、健康检查等后台服务。如有需要，可以把 App.xaml.cs 中的服务注册抽成可复用的扩展方法，但 WPF 的启动行为必须保持不变。

- 在进程内启动 1–2 个真实 Worker。

1. 注册加心跳后，节点变为 Online。
2. 创建任务后，经过分配、爬取，结果落库、状态为 Completed，且进度不回退。
3. 停掉一个 Worker 后，它被判为离线，任务重置并由另一个节点完成（测试中可以把超时配置缩短）。

测试要稳定：不要固定 sleep，用轮询加超时。整套测试控制在 2 分钟内，用 Trait 标记以便单独运行。
把运行方式（包括如何单独运行或排除集成测试）写进 CLAUDE.md 的“构建与测试”一节。
```

### T6 arXiv API 插件与任务分片

```text
新增一个基于 arXiv 官方 API（export.arxiv.org/api/query）的论文元数据插件，保留现有的 ThesisPlugin。
要求：
- 支持按学科分类加提交日期区间查询，并处理分页。
- parsedData 的输出键必须与 ThesisPlugin 完全一致（契约见 CLAUDE.md），DataAnalysis 不改代码就能读取。
- Master 端要能把一个“分类 + 年份范围”的采集需求拆成多个子任务（默认按年拆分），分发给多个 Worker。
- 遵守 arXiv 的限速要求：每 3 秒不超过 1 次请求，同一时间只开一个连接。多个 Worker 共用一个出口 IP 时，合计请求频率也不能超标。默认做法：Master 限制同一插件的任务同时只在一个节点上运行，或者用全局限速，二选一并在文档中说明理由。
默认决定（可以改，但要记录理由）：
- 一次 API 响应包含多篇论文，而导出 JSON 的契约是“每个 pageResult 对应一篇论文”。扩展插件结果，使其支持返回多条记录；引擎把每条记录展开成独立的 PageResult，Url 用论文的 abs 链接。保持对现有插件的向后兼容。
- 分页的处理方式由你决定：可以在拆分任务时直接生成各页的查询 URL，也可以通过链接跟随实现。
验证步骤：
1. 先用集成测试验证，用本地模拟的 API 响应。
2. 再用少量真实请求验证。
3. 最后采集 cs.LG 分类 2015–2025 年的数据，每年约 100 篇，交给 DataAnalysis 跑出跨年份的趋势图。结果记录在 docs/analysis/README.md，并把“数据全是 2026 年”的已知问题标为已解决。
导出的真实数据只保存在本地（D:\毕设相关\数据分析\元数据\ 下新建子目录），不要提交进仓库。
```

### T8 BERTopic 对比

```text
在 DataAnalysis 中加入 BERTopic 作为可选的主题模型，与现有 LDA 并列，界面上可以切换。
做对比实验：在同一数据集上比较主题一致性（C_V）、主题多样性和运行耗时，结果写进 docs/analysis/README.md。
主题多样性的默认算法：取所有主题各自前 25 个词，计算其中不重复词所占的比例。

```

### T9 任务暂停与取消

```text
实现任务控制功能。协议里已经定义了 TaskControl（Start/Pause/Stop/Cancel），目前界面和 Worker 端都没实现。

- 在 TaskStatus 枚举末尾追加 Paused、Cancelled，proto 同步追加，旧数据保持兼容。

- 已取消的任务不被故障恢复重新调度。
用集成测试覆盖“暂停 → 继续 → 取消”的完整流程，以及暂停期间节点离线的情况。界面部分列出复测步骤。
```
