# 任务书与开题报告要点（原计划范围）

> 来源：`2任务书.doc`（2025-11-30 下达）、`4开题报告.doc`（2025-12-14）。开题时的设想远大于最终实现（例如数据分析原计划用 .NET 全家桶，最终改为 Python + Streamlit）。未实现的部分可当作后续开发的需求池，✅/❌ 为截至 2026-10 的实现情况。

## 任务书

### 目标
系统能从公开学术数据源高效采集文献元数据，并用 NLP 与主题建模深度挖掘、可视化，用于发现研究热点、分析主题演化、探索合作网络。

**分布式爬虫管理模块**：分布式执行 ✅、实时监控 ✅、可视化调度（图形化设计和调度爬虫流程）⚠️（有任务管理 UI，无流程设计器）、插件化扩展 ✅、高可用（故障检测 + 任务重分配）✅。

**主题可视化分析模块**：
- 主题建模与数据分析子系统：文本预处理 + 关键词权重计算 ✅（LDA）；主题模型训练与评估，计算主题一致性 ✅、**主题多样性** ❌。
- 主题可视化分析子系统（参考 BTVis）：**主题概览视图**（主题层次聚类树，交互探索主题生成路径）❌；**文档分析视图**（降维散点图展示文档在主题空间的分布）❌（只有 pyLDAvis 主题间距离图）。
- **热点趋势视图**（参考统计建模大赛作品）：研究热点随年份变化折线图，辅助预测 ✅ 折线图 / ❌ 预测。
- **合作网络视图**：用作者共现或语义相似度构建作者关系图谱，挖掘合作社群 ❌。

## 开题报告

### 研究内容（四大模块）

1. **分布式爬虫管理系统**
   - Master（WPF + MVVM）：节点管理、任务调度（创建、**分片**、下发、重分配）、插件管理（上传、加载、更新、卸载）、**监控告警**（资源、进度、采集成功率、异常告警）、数据持久化。
   - Worker（.NET Console）：gRPC 通信；爬虫引擎（HtmlAgilityPack + AngleSharp，请求频率控制、**UA 池、代理池**）；资源监控（CPU、内存、**网络带宽**）。
2. **学术文献元数据采集**
   - 多源适配：arXiv、**CNKI、IEEE Xplore、万方**；提取标题、作者、摘要、关键词、发表时间、期刊/会议、DOI、**引用量**。
   - 预处理与规范化：缺失补全、异常过滤；基于 **DOI 或 标题+作者** 的跨平台去重；统一 `AcademicPaper` 数据模型。
   - 反爬：动态频率控制、随机 UA 池、代理 IP 池、Cookie 管理，遵守 robots 协议。
3. **数据分析与主题可视化**（原计划全部用 .NET 实现）
   - 预处理：.NET DataFrame / Deedle、Jieba.NET 中文分词、停用词。
   - 分析引擎：TF-IDF + LDA + **BERTopic** 主题聚类；ML.NET 趋势演化与新兴主题预测；**QuickGraph 作者-机构合作网络**（度/中介/紧密中心性、社区划分）；**Lucene.NET 全文检索**与相似文献匹配。
   - 可视化（WPF + LiveCharts2 / OxyPlot / Graphviz）：主题分布热力图、热点演化时序曲线、关键词共现网络、作者合作网络、机构发文量柱状图、年度发文趋势；缩放、筛选、下钻、联动、导出。
4. **系统集成与测试**：Master 与分析引擎数据互通、WPF 内直接可视化（一站式）；72 小时稳定性测试；不同 Windows 版本兼容性测试。

### 拟解决的关键问题
1. 可靠通信与智能调度：gRPC 双向流 + 故障检测/剔除/重分配；结合 CPU/内存/**网络带宽**的加权负载均衡，任务**动态分片**，保证**幂等**避免重复采集。
2. 多源异构元数据抽取与规范化：插件化解析框架；规则匹配 + 语义校验；统一模型 + 清洗/去重/补全。
3. 海量文本语义挖掘：并行预处理流水线；对比 LDA 与 BERTopic；**增量分析 + Redis/MemoryCache 结果缓存**。
4. 交互式可视化：多视图联动、低门槛操作（筛选、维度切换、下钻、导出）。

| 层 | 技术 |

## 与最终实现的主要偏离

- 分析模块从 .NET 改为 **Python（NLTK + Gensim + Streamlit）**，并且只处理英文（arXiv），没有中文分词。
- 数据源只有 arXiv；无去重模型 `AcademicPaper`、无反爬、无引用量。
- 两模块之间是 JSON 文件对接，没有在 WPF 内直接展示分析结果。
- 合作网络、BERTopic、全文检索、增量分析与缓存、监控告警、任务分片均未实现。
