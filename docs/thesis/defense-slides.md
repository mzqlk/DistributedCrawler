## 各页要点

**P1 封面** 讲稿：自我介绍，按背景、设计、关键技术、验证的顺序汇报。

**P3 研究背景**
- 每年新增论文 >300 万篇，年增长约 5%，信息过载。
- 传统方法：关键词检索只能看局部；各数据库格式不统一、数据孤岛。
- 现有工具：单机采集、架构耦合高、分析只到基础统计、无故障转移。
- 机遇：分布式爬虫解决采集瓶颈；LDA + 可视化快速洞察趋势。

**P4 研究目标与内容**：低耦合模块化系统。爬虫模块——负载均衡调度、节点监控与故障转移、插件化；分析模块——预处理流水线、可配置 LDA、多维交互可视化。

**P5 爬虫模块功能需求**：节点管理、可视化任务调度、实时性能监控、智能负载均衡、插件化引擎、数据持久化、故障任务恢复。

**P6 非功能需求与约束**：高可用、动态扩展、节点认证 + TLS；边界不含反爬破解、数据清洗分析、分布式存储；.NET 10 / gRPC(HTTP/2) / SQLite + EF Core / WPF。

**P7–8 分析模块需求**：JSON 批量上传与预处理、可配置 LDA + 指标、多图联动筛选、CSV 导出；易用性（线性流程 + 默认值）、性能（1000 条预处理 ≤15s）、兼容性（Win/Linux，Chrome/Edge/Safari）、鲁棒性。

**P9 架构原则**：高内聚低耦合（DI）、可扩展（插件热插拔、节点动态扩展）、高可用（无状态 + 故障迁移）、易维护（MVVM、日志）。

**P10 核心组件与数据流**：① 注册 → 验证 → 建双向流；② 提交任务 → 入队 → 调度 → 下发 → 执行并上报进度与结果；③ 心跳 → 更新状态 → SignalR 推前端。

**P11–12 通信与分析架构**：gRPC 单一长连接双向流 + `oneof` 封装；分析模块四层（交互/逻辑/算法/持久）；采集模块输出标准 JSON，分析模块直接读取。

**P13–14 Master 详细设计**：节点 Pending→Online→Offline，5s 心跳 + 30s 健康检查（2 分钟超时）；任务 Pending→Running→Completed/Failed，优先队列 + 负载均衡；SignalR 5s/2s 节流。（代码实际为 15s/1 分钟，见 `docs/project/overview.md` §5。）

**P15–16 故障恢复与 Worker**：订阅 Offline 事件 → Running 任务批量重置为 Pending（事务）→ 重新入队，重复处理锁；BFS 引擎 + URL 去重 + 深度限制 + 超时；资源监控兼容 Docker 与物理机；反射加载 `ICrawlerPlugin` DLL。

**P17 分析模块详细设计**：上传 → 预处理（NLTK）→ 训练（Gensim LDA）→ 可视化（Matplotlib + Plotly）→ 导出 CSV；`st.session_state` 保持状态。

**P18 爬虫关键技术**：资源感知负载均衡；gRPC 双向流 + 会话管理处理断连与会话失效；SignalR 实时同步；EF Core `AsNoTracking` + 按需加载避免 N+1；心跳超时检测 + 任务自动迁移。

**P19 分析关键技术**：字段提取 → 清洗 → 分词 → 词性标注 → 词形还原 → 去停用词；`LdaMulticore`；困惑度 + 一致性选 K；Streamlit 滑块/下拉实时联动。

**P20 部署与功能验证**：Docker 容器化（PPT 称 Master 和 Worker 都打包，实际只有 Worker 有 Dockerfile）；PPT 称“YAML 配置”，实际为 `appsettings.json`。

**P21 性能验证**：预处理 1000 条 ≤15s、训练 ≤100s、渲染 ≤2s，均达标；资源占用与可用性测试为定性描述。

**P22 总结**：完成设计与实现；高效可靠采集；深度交互分析；验证有效；可供参考。

**P23 未来展望**
1. 扩展数据源：IEEE、Springer 等插件。
2. 优化主题模型：结合 BERT 等预训练语言模型。
3. 增强可视化：作者合作网络、机构影响力分析。
4. 提升智能化：热点趋势自动预测、个性化文献推荐。
5. 优化性能：抓取效率与分析算法，支撑更大规模数据。
